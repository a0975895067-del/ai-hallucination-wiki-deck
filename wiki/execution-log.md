# 實際執行與檢查紀錄

## Run 01｜來源取得與第一次大綱

- 日期：2026-11-13
- ingest：6 / 6 篇成功
- 原子主張：24 條
- 第一次投影片：10 張
- 自動檢查結果：失敗 1 項

### 發現的問題

第一次大綱把 RAG 寫成「利用外部資料即可消除幻覺」。S3 只支持 RAG 能結合參數與非參數記憶，並在研究任務中產生更具事實性的內容；它不能支持「完全消除」。

### 修正

改寫為：「RAG 讓回答可參照外部知識並改善來源追溯；但檢索錯誤、來源品質與生成不忠實仍可能造成問題。」

## Run 02｜把檢查往前移

- 在 Wiki ingest 階段新增「限制」欄位。
- 在進入大綱前，先檢查每個主張是否有來源 ID、證據範圍與限制。
- 投影片加入 `data-source`，由 `npm run check` 自動比對 manifest。
- 自動檢查結果：通過。

## 最常出錯的節點

「整理重點 → 產生教學大綱」最容易出錯。模型會把研究結果壓縮成好記的口號，但也可能把「降低」誇張為「消除」，或忽略研究情境。

## workflow / graph 修改

原流程把引用檢查放在 HTML 完成後。實際執行後，將檢查提前到「Ingest Wiki → 原子主張與限制檢查」，再允許進入大綱。這樣能在錯誤擴散到多張投影片前攔截，減少重做成本。
